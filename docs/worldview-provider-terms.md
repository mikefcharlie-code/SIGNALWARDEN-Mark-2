# World View provider terms and attribution

These integrations are read-only and opt-in. The provider links below are the primary references for source credits, data-use limits, credentials, and display terms; each displayed result must retain its provider timestamp, retrieval time, attribution, and source link where supplied. This implementation does not convert public feeds into flight-control inputs, mission commands, or effector actions. Provider configuration remains disabled by default on the server, and UI consent is separately required.

## Behavior and separation

Public requests require an explicit user action or session opt-in; imagery and tile requests are tied to the currently visible globe viewport and are aborted or cleared when the relevant panel/globe is closed. Server-side credentials are never sent to browser code. Malformed responses, failed refreshes, stale provider timestamps, unknown freshness, and provider throttling remain distinguishable from live/fresh data. Georeferenced image pixels are placed only from validated transforms or the exact WMS WGS84 request extent and are clipped by the separate imagery-AOI mask; imagery AOIs are not flight-control geofences. Public data are advisory display-only and are not passed to aircraft command, mission, or effector functions.


## Sentinel browse georeferencing boundary

The current ASF Search API response used here supplies scene metadata, a geographic footprint and an optional browse JPEG; that browse asset does not provide a raster CRS/affine transform. Do not infer image placement from the footprint. ASF's official [Search API basics](https://docs.asf.alaska.edu/api/basics/) says product downloads require an Earthdata Login account. The NASA [Sentinel-1 GRD geocoding recipe](https://www.earthdata.nasa.gov/learn/data-recipes/geocode-sentinel-1-arcgis) explains that GRD TIFFs contain georeferencing information, but remain in SAR geometry; geocoding/terrain correction requires separate processing. ASF's [RTC product guide](https://hyp3-docs.asf.alaska.edu/guides/rtc_product_guide/) describes processed GeoTIFF products and their map projection. Accordingly, this integration keeps Sentinel browse JPEGs as footprint-pinned, explicitly non-georeferenced previews; it does not label them live or drape them. Georeferenced display is supported only when actual source transforms are validated (Umbra GeoTIFF, nowCOAST WMS bbox, and user-selected local GeoTIFF). A future Sentinel drape requires an authorized actual product/RTC workflow and validation, not an inferred transform.
