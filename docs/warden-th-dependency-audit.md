# Warden local ONNX dependency and license audit

The Warden-TH and Warden-NAV CPU inference groups use exact pins for NumPy 2.2.6 and ONNX Runtime 1.31.1. The NAV-only training/export file adds ONNX 1.23.2; exporter dependencies are separate from the inference runtime. NAV requirements are in `requirements-ai/navigation-integrity.txt` and `requirements-ai/navigation-integrity-training.txt`.

Installed package metadata was checked for the pinned runtime and its dependency closure. NumPy 2.2.6 declares BSD-3-Clause; ONNX 1.23.2 declares Apache-2.0; ONNX Runtime 1.31.1 declares MIT. Runtime dependencies include FlatBuffers 25.12.19 (Apache-2.0), Packaging 26.3 (Apache-2.0 OR BSD-2-Clause), Protocol Buffers 7.36.2 (BSD-3-Clause), and typing_extensions 4.16.0 (PSF-2.0). The training closure also includes ml_dtypes 0.6.0 (Apache-2.0). The NumPy wheel carries additional notices for bundled math/runtime libraries; those notices remain part of the installed distribution.

`pip-audit` 2.10.1 scanned both pinned NAV requirements files and their resolved dependency closure: **no known vulnerabilities found**. The management web production dependency audit (`pnpm audit --prod`) also found **no known vulnerabilities**, and `pnpm licenses:check` verified notices for 16 packages. No frontend package was added for NAV.

The ONNX model and calibration are generated by project code from seeded synthetic telemetry only; no third-party dataset or pretrained weight is included. The repository has not selected a license for these generated artifacts, so both are marked `NOASSERTION`; that is not a grant of permission for third-party use. Their SHA-256 pins are recorded in `configs/warden-nav-artifact.json` and `configs/local-ai-models.json`. Weights remain outside Git and have no automatic download route. Public logs remain out of scope until license review.
